# 프로필 수정 (data/site.json)

호출 인자: `$ARGUMENTS`

## 1단계: 섹션을 정한다

| 섹션 키 | 이렇게 불러도 됨 | 화면 위치 | 들어 있는 칸 |
|---|---|---|---|
| `hero` | 첫화면, 메인, 히어로, 대표문구 | 맨 위 첫 화면 | `title`(큰 제목), `lead`(소개 한두 줄), `photo`(프로필 사진) |
| `about` | 소개, 경력, 연혁, 이력 | 소개 + 경력 | `heading`, `intro`, `points[]`(`title`/`desc`), `careerLead`, `timeline[]`(`year`/`text`) |
| `services` | 서비스, 가격, 패키지, 진행순서 | 서비스 안내 + 진행 순서 | `heading`, `lead`, `items[]`(`title`/`desc`/`price`), `stepsTitle`, `steps[]`(`title`/`desc`), `note` |
| `cta` | 문의, 문의문구 | 아래쪽 문의 칸 | `title`, `lead` |
| `contact` | 연락처, 카톡, 카카오, 이메일, 메일 | 문의 칸·아래 고정 바 | `kakao`(오픈채팅 주소), `email` |
| `brand` | 이름, 브랜드 | 상단 이름, 사진 설명 | 글 하나 |
| `meta` | 제목, 탭제목, 미리보기 | 브라우저 탭·카톡 미리보기 제목 | `title` (`siteUrl`은 바꾸지 않는다) |
| `footer` | 푸터, 저작권 | 맨 아래 한 줄 | 글 하나 |

**인자가 있을 때** — 위 표의 키나 별칭으로 섹션을 찾아 바로 2단계로 간다. "경력"처럼 칸 하나를 가리키는 말이면 그 칸(`about.timeline`)부터 묻는다.

**인자가 없거나 표에 없는 말일 때** — 아래 형식으로 섹션 목록을 보여 주고 고를 때까지 기다린다. 다른 작업은 하지 않는다.

```
어느 부분을 고칠까요? 번호나 이름으로 알려 주세요.
1. 첫 화면 (hero): 큰 제목, 소개 한두 줄, 프로필 사진
2. 소개·경력 (about)
3. 서비스·가격·진행 순서 (services)
4. 문의 문구 (cta)
5. 연락처: 카톡, 이메일 (contact)
6. 이름 (brand)
7. 탭·미리보기 제목 (meta)
8. 맨 아래 문구 (footer)
```

**다른 스킬로 넘길 것** — 후기(`reviews`)는 `write-review`, 예식 일정(`schedule`)은 `manage-schedule`, 앨범과 사진 파일(`album`, `hero.photo` 사진 교체)은 `add-image` 스킬로 넘긴다. 이 스킬에서 직접 고치지 않는다.

## 2단계: 지금 내용을 보여 주고 되묻는다

시작 전에 `git pull --rebase origin main`을 한 번 한다. 그다음 고를 섹션의 지금 값을 보여 준다(`about` 자리에 섹션 키):

```bash
python3 -c "import json,sys;print(json.dumps(json.load(open('data/site.json'))[sys.argv[1]],ensure_ascii=False,indent=2))" about
```

JSON을 그대로 보여 주지 말고, 칸마다 번호를 붙인 한국어 목록으로 바꿔 보여 준다. 배열은 항목마다 번호를 붙인다. 그 뒤에 묻는다: "어느 칸을 어떻게 바꿀까요?"

- 한 번에 여러 곳을 말해도 된다. 대신 바꿀 곳과 새 문구가 모두 분명해질 때까지 되묻는다. 새 문구를 지어내지 않는다. 사용자가 "좀 더 매끄럽게"처럼 다듬어 달라고 한 경우에만 안을 2~3개 내고 고르게 한다.
- 배열 칸(`points`, `timeline`, `services.items`, `steps`)은 추가·수정·삭제·순서 바꾸기 중 무엇인지 확인한다. 화면은 배열 순서대로 그린다. `timeline`은 최신 연도가 맨 앞이다.

## 3단계: 칸별 규칙을 지켜 고친다

- 줄바꿈은 문자열 안의 `\n`. HTML 태그를 넣지 않는다(글자로 그대로 보인다).
- 연도도 문자열: `"2026"`.
- 빈 문자열인 칸은 화면에 아예 나오지 않는다. 지우고 싶다는 말은 `""`로 비운다는 뜻일 수 있으니 확인한다.
- 링크·사진 경로는 `https://`, `mailto:`, `images/`로 시작해야만 화면에 나온다. `contact.kakao`는 `https://open.kakao.com/`으로 시작하는지 확인한다.
- `services.items`의 가격은 지금 `title` 안에 `"일반 사회 · 200,000원"`처럼 들어 있다. `price`는 가격 아래 작은 글씨(예: 출장비 안내)다. 가격을 바꿀 때는 `title`의 숫자를 고친다.
- 경력 연수(예: "웨딩 MC 7년")는 `hero.lead`, `about.points`에 함께 나온다. 한 곳을 바꾸면 다른 곳에도 같은 숫자가 있는지 찾아보고, 같이 바꿀지 묻는다.
- 연락처 칸에 개인 휴대폰 번호는 넣지 않는다. 모든 파일이 공개된다.

저장은 기존 형식 그대로 한다(들여쓰기 2칸, 한글 그대로, 맨 끝 줄바꿈):

```python
import json
p = 'data/site.json'
d = json.load(open(p, encoding='utf8'))
# d['about']['timeline'].insert(0, {"year": "2026", "text": "..."})
with open(p, 'w', encoding='utf8') as f:
    json.dump(d, f, ensure_ascii=False, indent=2)
    f.write('\n')
```

### 카카오톡 미리보기 같이 맞추기

`meta.title`(또는 그게 비었을 때 `brand`)과 `hero.lead`는 `index.html` `<head>`에도 들어 있다. 이 값을 바꿨으면 `index.html`의 `<title>`, `<meta name="description">`, `og:title`, `og:description`도 같은 글로 바꾼다. 따옴표·`&`·`<`는 HTML용으로 바꿔 쓰고(`&quot;`, `&amp;`, `&lt;`), 줄바꿈은 그대로 둔다. 카카오톡은 미리보기를 캐시하므로 바로 안 바뀔 수 있다고 알린다.

## 4단계: 확인한다

1. 문법 확인: `python3 -m json.tool data/site.json > /dev/null`
2. **마지막 단계**로 간다. 커밋 메시지 예: `서비스 가격 수정: 일반 사회 220,000원`

## 마지막 단계: 바뀐 내용 보여 주기 → 반영(푸시)은 요청받았을 때만

### 1. `git diff`로 변경 전·후를 보여 준다

파일을 고쳤으면 **항상** 실행한다:

```bash
git status --short -- data/ images/ index.html
git diff -- data/site.json index.html
```

- diff 원문을 그대로 붙이지 말고, 바뀐 곳마다 **변경 전 → 변경 후** 표로 정리한다. `-` 줄이 변경 전, `+` 줄이 변경 후다.

  | 위치 | 변경 전 | 변경 후 |
  |---|---|---|
  | `reviews.items[0]` | (없음) | 김○○ 신부님 · 2026년 5월 · "사회 덕분에…" |
  | `services.items[0].title` | 일반 사회 · 200,000원 | 일반 사회 · 220,000원 |

- 새로 넣은 파일(`??`)과 지운 파일(` D`)은 diff에 내용이 안 나오므로 status 결과로 따로 적는다.
- 이번 작업에서 고치지 않은 변경이 diff에 섞여 있으면 "이번 작업과 무관한 변경"으로 구분해 알린다.
- 끝에 한 줄 덧붙인다: "공개 사이트에 반영하려면 '반영해줘'라고 말씀해 주세요."

### 2. 커밋·푸시는 사용자가 직접 요청할 때만, 그리고 한 번 더 묻는다

- 사용자가 "반영해줘", "푸시해줘", "공개 사이트에 올려줘"처럼 **공개 사이트 반영을 직접** 말하기 전에는 커밋도 푸시도 하지 않는다. "좋아요", "확인했어요", "고마워요"는 반영 요청이 아니고, 스킬을 부를 때의 "후기 올려줘"·"사진 올려줘"도 파일을 고쳐 달라는 뜻일 뿐 푸시 요청이 아니다.
- 요청을 받아도 바로 하지 않고 **한 번 더 묻는다**:

  ```
  아래 내용으로 공개 사이트에 반영(푸시)할까요? 푸시하면 1~2분 뒤 누구나 볼 수 있습니다.
  - 올릴 파일: data/site.json, images/20261020_review-202605-kim-bride_image_1.jpg
  - 커밋 메시지: 후기 추가: 김○○ 신부님 (2026년 5월)
  '예'라고 답해 주시면 진행합니다.
  ```

- '예', '네 올려줘'처럼 분명히 승낙한 경우에만 3으로 간다. 답이 애매하거나 고칠 곳을 말하면 푸시하지 않고, 고친 뒤 1부터 다시 한다.

### 3. 반영

1. 이번 작업에서 바꾼 파일만 이름을 적어 `git add` 한다(`git add -A`, `git add .` 금지). 내용 파일(`data/`, `images/`)과 그 밖의 파일(`index.html` 등)은 커밋을 나눈다.
2. 커밋 메시지는 한국어로, 첫 줄에 무엇을 바꿨는지 쓴다.
3. 푸시 바로 전에 `git pull --rebase origin main`. 충돌이 나면 `git rebase --abort` 하고 푸시하지 않은 채 알린다. 커밋하지 않은 다른 변경 때문에 pull이 거부되면 stash 하지 말고 멈춰서 알린다.
4. `git push origin main`. `--force`는 쓰지 않는다.
5. 푸시한 커밋(해시·메시지)을 보여 주고, 1~2분 뒤 공개 사이트에 반영된다고 알린다.

## 꼭 알릴 것

**아티팩트(claude.ai 편집 화면)의 '공개 사이트에 반영'은 `data/site.json`을 통째로 덮어쓴다.** 여기서 고친 내용을 아티팩트에도 고쳐 두지 않으면 다음 반영 때 원래대로 돌아간다. 끝날 때 한 줄로 알린다.

## 흔한 실수

- 섹션 목록을 보여 주기 전에 마음대로 섹션을 골라 고침.
- 사용자가 말하지 않은 문구를 지어 넣음.
- 가격을 `price` 칸에 넣어 가격이 두 번 보임.
- `hero.lead`·`meta.title`만 고치고 `index.html` 미리보기는 그대로 둠.
- `timeline`에 새 연도를 맨 뒤에 넣음.
- 사용자가 반영을 직접 요청하지 않았는데 커밋·푸시함. 요청을 받고도 한 번 더 묻지 않고 바로 푸시함.
- `git diff`로 변경 전·후를 보여 주지 않고 "고쳤습니다"로만 끝냄.
